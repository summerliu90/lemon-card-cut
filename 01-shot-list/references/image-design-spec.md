# 图片设计交接规范

## 先确定数量和制作方式

先给推荐方案的确定数量，不只给“约5–10张”。存在素材缺口时给基准数及增减条件。区分：

- C编号：视频中有独立身份的卡片容器。
- I编号：需要独立设计的图片；一图跨镜复用只算一张。卡片可使用同一图片的不同裁切，一个卡片也可容纳多个图层。
- L编号：独立动态层，例如参数标记、选中框、错误提示、连线。标明用文字/矢量绘制还是需要透明PNG。
- BG编号：背景；纯色、网格等适合直接绘制，不默认占用生图次数。
- V编号：情境、氛围或操作视频，单独按[视频素材规范](video-asset-spec.md)规划；不混入独立图片或生图次数。

数量汇总必须写：独立图片设计共几张；其中建议AI生图几张、程序排版/矢量绘制几张、使用现有图片几张；另有透明图片层几张；预计导出图片文件共几份。模型调用次数因重试和批次而变，不等同于图片数。不要为了凑数量把适合直接排版的标题、按钮、箭头都做成生成图片。

新增状态优先用同一底图叠加动态层；若必须导出多张状态图，逐张列出文件名并计数，保持布局一致。

## 图型推荐

先读[图片选型库](visual-design-catalog.md)。除下表外，主动考虑概念解释、组成拆解、实例批注、正误对照和知识地图；diagram_type描述组织关系，visual_treatment描述手绘笔记/白板/教材等表现，两者不互相替代。全片搭配在01决定，02不能仅因方便就把所有图变成同一排版。

“信息图”描述信息组织，“白板图”描述视觉风格，允许组合，例如“流程图＋白板手绘风”；不能只说“白板图”却不设计信息关系。每张选择一个主图型，说明与口播信息的对应理由。

| 信息关系 | 推荐主图型 | 应设计的内容 |
|---|---|---|
| 多个并列要点、能力总览 | 信息图 | 分组、主次、阅读顺序，避免罗列整段口播 |
| 系统组成、任务分工、上下层关系 | 结构图 | 模块、层级、归属，区分组织关系和执行顺序 |
| 有先后顺序、回路或关卡 | 流程图 | 入口、步骤、箭头、判断、终点/回流 |
| 解释概念、推理过程 | 白板讲解图（注明结构/流程等主图型） | 少量关键词、示意对象、连接关系、留白 |
| 前后差异或方案对照 | 对比图 | 同维度左右对齐，突出差异 |
| 操作过程或产品能力 | UI示意/真实截图 | 控件、节点、选中态；示意必须标明，真实截图需来源 |
| 资料预览、目录、领取物 | 清单/文档长图 | 实际条目、章节、滚动停留位置 |
| 情绪、情境、开头隐喻 | 场景插画/照片 | 主体、动作、环境、文字留白，避免代替技术解释 |

不为了画面变化给每张强行使用不同风格；全片统一卡片边框、字体与颜色语义。

## 每张图片的任务书

对每个I编号完整填写，不能要求下一步“参考上文”补内容：

1. **身份与用途**：ID、建议文件名、对应镜号/口播、绑定C编号，解决观众哪个理解问题。
2. **主图型＋表现风格＋理由**：例如“节点流程图＋简洁白底UI风，说明参数流向与错误位置”。
3. **画面内容**：逐一列出对象、数量、名称、关系和箭头方向。区分用户原文事实、必要解释与示意例子；不扩展未经支持的技术结论。
4. **构图**：横/竖比例、像素、阅读方向、各区占比、主体位置、留白、安全边距；说明素材自身构图，不把整片字幕一起做进卡图。
5. **准确文字**：标题、标签、注释逐字列出。需后期排字则标明“底图不含文字”，逐项指定文字落位；复杂中文/长文档优先程序排版，避免依赖生图准确输出密集文字。
6. **色彩与形态**：背景、强调色及含义、线条、图标风格、圆角、阴影，保持系列一致。
7. **分层和状态**：静态底图画什么，哪些内容另为L层，是否透明，初始/结束状态；后期要单独动的元素不得预先合并到整张图里。
8. **裁切与可读性**：视频中的显示尺寸、重点区域、是否局部放大。不能让下一步以做海报的方式堆入不可读内容。
9. **禁止项**：针对该图列出容易误画的内容，如虚构品牌界面、无意义英文、额外节点、乱向箭头、字幕/领取话术入图。
10. **独立设计指令**：把以上决策汇成一段自包含指令，下一步即使只拿这一段也能画对。按实际制作路线称为生图提示词、SVG/排版任务或截图处理说明；不要把所有图都强制交给生图模型。

任务书同时记录diagram_type、visual_treatment、selection_reason、learning_goal及content_basis（原文/用户素材/标明的说明性示例）。若多个候选都适用，保存候选与最终选择理由；启用随机时记录seed和已选结果，不随机生成技术结论。竖版密集图明确选横屏重排、模块拆分或局部窗口浏览，不能只写等比缩小。

## 动态图的交接示例

口播：“节点能修改，参数能传递，失败能定位。”

推荐I05：一张节点编排UI示意底图，绑定C05；主图型为流程图，白底UI风。中心区域从左至右为“设备接入→执行节点→结果”，连线水平，卡内上方保留标题位，节点下方留错误提示位。示意表达能力，不代表任何真实产品。

- I05底图仅含中性节点框、连线和准确节点标签；若需后期排字则底图只保留框和线。
- L01：配置面板，以矢量框和文字“超时：10s→20s”制作，属于示意参数。
- L02：参数传递标记，以矢量绘制，沿底图连线运动。
- L03：错误高亮和定位面板，以矢量绘制，文案“失败节点 / 错误原因 / 日志入口”。
- 三个L层均为后期元素，不需要3张额外AI图片，避免把整个流程图生成三遍造成节点跳动。若制作工具要求PNG导出，另计3份文件。

具体任务中仍须补足尺寸、节点坐标、颜色和完整设计指令；本例仅解释拆层原则。

## 交接验收

脱离聊天上下文能否明确“共做几张、每张是什么、具体画哪些、文字是什么、怎么排、哪些会动”？卡片与图片映射、导出文件和数量是否相符？如果下一步还要自行决定关键节点或凭空补充卡面文字，01-shot-list尚未完成。

画风、候选随机、比例和双竖图的完整字段及跨阶段门禁见[图片画风执行契约](visual-style-contract.md)，新增项目同时交付visual_design结构化数据。
