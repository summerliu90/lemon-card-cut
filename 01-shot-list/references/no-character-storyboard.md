# 无人物动态卡片分镜规划规则

本风格的材质、构图主次与动效默认先执行[稳定系列规划](series-visual-standard.md)及其无人物提示词，语义分镜再按本文件选择。完整主插画不强拆；独立素材仅用于需分别运动的对象。此前项目例子不覆盖系列profile。

## 适用范围与顺序

冻结的 `task.style` / 计划 `style_id=no-character`（飞书「10 无人物动态卡片」），且制作模型为本skill的动态分镜路线时，01、02、04读取本规则。小黑、小柠檬及PPT路线不加载它；模型编号不代替风格选择。沿用任务指定背景、音色和已审核口播。

默认顺序：核对输入 → 保存并校验01分镜与素材任务书 → 准备图片、图层及原生文字 → 按真实配音校准 → 实际审看代表样片 → 全片与可编辑剪映草稿 → 分项验收。先规划再提交新出图；需要改镜时先更新01及对应动作。视觉返工优先复用合格配音与素材。

本规则将kb-050中已采用的对象分步展开、表格对照、表单传参提炼为后续默认方法；不把该项目尚未完成的连续审看和审听描述为已通过。固定的是方法，不是17镜、9图、6张表、某个行业案例或网格背景。

## 无人物的视觉语言

- 用知识对象、图标、流程、连接、字段、状态与准确文字承担叙事，不生成角色、IP、人脸、手部、拟人动物或表情包，M=0。真人/手部素材默认关闭；用户明确开启时按既有 `footage_policy` 执行，并标明“无人物图文＋真人实拍混合”。
- 顶部章节、中部解释对象、底部口播字幕可作为基本分区，按内容调整布局。保留指定背景及其可见性约定；可用白色阅读舞台，但不能无意遮满背景。
- 按“观众本镜需要理解什么”选择图型，不把所有镜头做成同一种三列图、文字页或表格。插图负责具体对象/空间关系，表格负责同维度比较，表单负责字段与输入输出关系。

## 按语义选择分镜

| 解释任务 | 画面设计 | 对象动作与保留结果 |
|---|---|---|
| 提问、误区与判断 | 左右两种做法或局部线索与完整证据对照 | 先建立问题，再揭示差异，结论与证据同屏 |
| 组成、层级与依赖 | 模块图、分层图、树状或流程结构 | 对象依次建立，连接落在真实端点，最后保留完整关系 |
| 单点做法与完整方法 | 同维度三列表：核对维度／当前做法／补足做法 | 表头先建立，逐行展开，保留已出现的行供对照 |
| 看似成功与实际异常 | 核对项／表面结果／业务证据（示例） | 区分接口结果与业务结果，异常标在对应行；颜色配合明确文字 |
| 上下游字段与参数关联 | 响应、请求或输入、输出两张表单 | 同一标识从来源移向目标，目标字段从未关联变成相同值，来源和最终值可核对 |
| 正常、边界与非法条件 | 数据类型／示例输入／预期结果 | 先给示例规则，再逐行呈现条件与结果，不能把示例写成项目事实 |
| 多层一致性核对 | 核对层／业务预期／示例实际／判断 | 按层建立证据，突出不一致；只看到Success不能直接判定整体成功 |
| 旧方法与新方法总结 | 同维度旧写法／新写法对照 | 复用已讲维度，完整结果停稳后再结束或进入原稿互动 |

上述方法按内容选择，不要求每片全部使用。没有可比较维度时不强加表格；复杂表拆成多个解释步骤或局部放大。具体字段、条件、判断从本稿推导，不照搬kb-050的订单、库存或券案例。

## 表格、表单与可读性

- 先写列含义、每行准确内容和比较维度，再定列宽、行高、字号及上屏时段。同行比较同一对象/条件，不能错行、错列或混淆预期与实际。
- 表头、单元格、字段值、结论和说明使用原生可编辑文字，不依赖生图生成准确中文。表格边界、纯色底板和连线可用原生形状；当前执行器需要时可用几何底板PNG，记录为几何素材，不宣称为可编辑表格单元格或API插图。
- 文字颜色按其实际背板选取：白色卡片上用深字，深色表头上用浅字。说明与脚注也要完整位于阅读区，检查文字真实边界，不能跨白卡与背景而一半不可见。
- 表头建立后按口播逐行/字段展开；已经建立的比较项保持可见，完整表留出实际可读的阅读窗，不刚出现就切走。数值单位、条件及示例标记随对应内容展示。
- 表单传参需明确来源、目标、同一字段和值、变更前后状态；移动结束后目标值真实更新，不能仅让一个标签横移而表单仍不关联。

素材边界、白底/透明选择及层到整图衔接按[素材拆层、底色与画面连续性](asset-layer-continuity.md)执行；表格使用原生文字/几何底板，不从整张含字图硬切单元格。

## 分镜与素材交接

在现有 `execution_contract.scenes` / `visual_beats` 中保存原口播、理解目标、主体、构图、素材ID、阅读窗与验收点。`objects` 记录中心/尺寸/z层级、准确文字、可见时段及初末状态；`asset_requirements` 声明独立对象、行底板、字段、连接及来源；`action_specs` 记录对象、镜内起点、时长、支持的属性、from/to、缓动与可观察结果。Markdown与JSON同步，布局坐标与执行器位移坐标不能混用。镜头时间按真实配音校准，缺词级对齐时标明估算。

AI插图只调用 `02-images/scripts/generate_image.py`，按 `.env` 通道从第 1 条开始，无法出图或超时才试后面的，不用内置imagegen，也不用程序绘图代替承诺的API插图。保留脱敏结果、真实文件与hash，不记录密钥。复用/裁切/拆层记录原图与操作来源，不把派生图层算作新生图；API失败或结果未知先检查已有结果，不静默反复提交付费任务。原生排版与几何表格不计为主体插图，不借此削减已规划的有效知识素材。

## 动作与验收

动作顺序是“对象建立 → 关系/操作推进 → 状态确认 → 完整结果停稳”。使用分步展开、字段传递、连接、筛选、分支或状态变化服务解释；不能用整图微缩放、统一铅笔扫屏冒充内容动态。只使用实际支持的关键帧，普通文字不强加当前路线不支持的alpha动作。

规划入场路径和最终位置，避让标题、标签、脚注及字幕。沿用生产配置的原生字幕；表格文字与口播字幕分开。API图裁切和重排不得拉伸对象或丢失信息；拆层切完整图时避免跳位、重影和白底残片。

样片覆盖所选关键方法，例如逐行表格和字段传递，再扩展全片。草稿与MP4共用同一执行计划；回读真实素材与字幕段，检查进入、动作中、停稳、退出画面，核对行列内容、字段值、示例条件、配色和字幕安全区。机器结构检查、多阶段帧审看、全片连续审看、人工审听、剪映打开及播放分别记录；未做项保持未完成，不以计数或联系表冒充连续验收。

固定本规则不自动重做旧项目、不调用付费接口、不回写飞书或发布。
