# 小柠檬IP分镜规划规则

本风格的材质、构图主次与动效默认先执行[稳定系列规划](series-visual-standard.md)及其小柠檬提示词，语义分镜再按本文件选择。完整主插画不强拆；独立素材仅用于需分别运动的对象。此前项目例子不覆盖系列profile。

## 适用与生产顺序

冻结的 `task.style` / `style_id=lemoner` 时使用，对应飞书「8 小柠檬IP」；制作模型还须是本skill的动态分镜路线。不要由模型编号推断角色，不覆盖表内选定背景或声音。小黑、无人物及PPT路线不加载本规则。

默认顺序：读取已审核口播和制作配置 → 保存并校验01逐镜方案与图片任务书 → 按方案准备/生成图片 → 按真实配音校准 → 制作并审看代表样片 → 合成视频和可编辑草稿 → 实际画面及应用内验收。已有音频可先核对后用于规划，不因视觉返工重配音。先把01落盘，再提交新的付费出图；制作中确需改镜时，记录变更原因及受影响素材，更新01再继续。

本规则提炼自kb-049的实际制作和发现的标签错位问题，是后续小柠檬项目的默认方法；不将该项目尚未完成的全片连续审看/审听描述为已通过，也不以结构检查代替视觉质量判断。

## 角色与整体视觉

- 使用并查看 `../../02-images/references/lemoner/ip-canonical.png`，保存项目参考副本、hash及身份检查。亮黄略扁宽柠檬头、短褐茎与绿叶、圆黑眼镜、米色脸、浅蓝背带裤、白胸牌“点工”；详细身份以[角色规范](../../02-images/references/styles-and-stickers.md#小柠檬身份锁)为准。只变化姿势、道具及轻微表情，不重设计角色或拉伸身体。
- 主体为粗深线、二维扁平色、亮黄与蓝色的清晰教学插图。角色承担提问、递资料、检查、展示结果等具体动作，不长期固定在角落充当装饰，也不要求每张技术图都塞角色。局部插图画风继续按逐素材设计契约声明，不能偷偷替换IP身份。
- 画幅默认16:9、1920×1080。顶部章节，中部解释对象，底部原口播字幕。白色阅读舞台可以使用；底层背景按当前任务选择，不能固定强制十字格。准确中文、判断和步骤标签保持原生可编辑，普通字幕继续使用生产配置的新青年体、字号7、黄字黑边。

## 按语义选择分镜

先确定观众本镜要理解的关系，再选择构图、对象和动作。下列是可复用方法，日志/接口名称只是例子，不能把kb-049技术内容复制进无关新稿。

| 关系与用途 | 分镜方法 | 动作与最终结果 |
|---|---|---|
| 提问、两端判断 | 两侧放待比较对象，小柠檬处于问题中心；也可用双区构图 | 对象分别建立，角色承担判断动作，最后保留两侧与问题 |
| 误区与证据不足 | 单一错误线索对照完整证据范围，例如只搜红字与海量日志 | 先给局部做法，再揭示遗漏证据；不能仅把标题换成“误区” |
| 多来源、分层定责 | 按来源/职责并列、分层或剖面排列 | 每层对象和其准确标签同步出现，最后保持可比较全貌 |
| 隐性故障、流程中断 | 将输入、处理、结果组成故障实例 | 先建立正常关系，再明确缺项、断点或不一致，异常落在正确对象 |
| 资料与能力组成 | 小柠檬递资料，按真实口播展开内容模块 | 资料或道具展开，主题名称逐项呈现；领取口令仅取原稿已有内容 |
| 请求与标识追踪 | 把ID、请求、记录设计为真实独立对象 | 标识实际从来源移向对应记录，或沿真实关系传递；不能用通用铅笔扫屏代替 |
| 筛选与上下文还原 | 区分匹配/不匹配记录，必要时展示父子调用 | 无关对象移出或淡出，匹配关系保留，父子/上下游关系明确建立 |
| 过程核对与根因上报 | 以入参、步骤、出参、数据结果作为证据序列 | 逐项核对、突出断点，再显示根因与其证据；不把症状当结论 |
| 方法对照、总结与互动 | 保持同维度对照，汇总已解释的方法，角色展示结果 | 完整结果停稳后提出原稿问题或行动，不额外编造承诺 |

数量由文案与阅读需要决定，不固定13场、9图、27层、三列布局或每镜3—5秒。三组对象并排只适合三项可比较关系；流程可沿路径展开，父子关系可树状，前后状态可双区对照，复杂证据可放大局部。复用同图要承接已建立状态、改变实际解释焦点；没有新解释任务时不反复全图入场。

## 逐镜必须明确的数据

按现有 `execution_contract.scenes` / `visual_beats` 协议交付，不发明不能编译的字段：

1. 原口播片段、理解目标、画面主体、构图及素材ID。
2. `objects`：中心、尺寸、z层级、准确文字、可见时段、初末状态及跨镜保留/替换/移除。
3. `asset_requirements`：真正需要独立运动的插图、角色/道具、连接、状态标签和表情；明确原图及派生层来源。
4. `action_specs`：对象ID、镜内起点、时长、真实支持的属性、from/to、缓动与可观察结果。0—1布局坐标与执行器-1—1位移坐标分别记录。
5. 阅读窗、字幕安全区、过渡与验收点。镜头边界取真实配音；缺少词级对齐时，镜内触发仍标估算。

共用学习库时保存真实配方引用和快照；本项目原创动作用 `motion_ref=null, origin=original`，不把本表冒充已学习配方或已验证动画。人读Markdown与JSON须同步，不能只有一句意图或只在脚本中临时设计。

## 图片、拆层与动作落实

AI插图只调用用户本地已配置图片API，继承当前提供方/模型/顺序，不使用内置imagegen，不用程序绘图冒充约定的API插图。密钥不入skill、提示词或日志。保存脱敏调用结果、实际图片及hash。API失败或服务端结果未知时记录状态，先恢复已有结果，不静默反复提交付费请求。

需要单独运动的对象优先准备独立素材，执行[素材拆层、底色与画面连续性](asset-layer-continuity.md)。不默认生成总图后按预设矩形拆开；只有实际主体边界清楚、完整无重叠/共享连接时才可安全裁切。白底知识图默认保留，去背景仅用于01明确需要透明的独立对象。合格图的安全裁切、遮罩或等比重排作为衍生素材，记录来源、裁切边界、编辑操作及hash，不把衍生层数当新增生图数。精确文字、连线和纯色舞台可用原生排版；不把这些计为主体插图。

API返回方形或其他尺寸时，先看对象是否完整；不得把已裁掉的手脚、设备或证据硬拉伸进横屏。可对完整对象等比重排并更新素材规格；无法恢复的对象应修正或补图。拆层后逐层检查邻近碎边、人物边缘和白底残片；切换完整图前后位置与比例应一致，不跳位、重影或闪白。

动作遵循“对象建立 → 关系/操作推进 → 状态确认 → 完整结果停稳”。除了进入方向变化，还需有适合当前知识的传递、过滤、连接、断点或状态变化；不靠整图微缩放、单一指示笔横移或角色抖动冒充解释。现有数值关键帧路线中，普通文字不强加不受支持的alpha关键帧；选实际支持的位移等动作，或先实现并验证其他路线。

## 图文对应与画面验收

- 标签跟随它解释的对象。前端JS/参数/拦截器的说明不能放到后端服务器下；网关名称不能落到浏览器下。某一对象只作后续层提示时明确写“下一层/最后兜底”，不能暗示本镜已经判定其故障。
- 图中成功/失败状态、连接方向、流程断点与口播一致。未建立前置条件不先显示成功。症状、定位线索、责任层和根因分开表达，避免图示擅自绝对化口播中的“多半/可能”。
- 检查整个入场路径而非只查停稳坐标；按对象真实边界避开标题、标签和字幕。准确标签保持可读，不用完整段落挤进图内。
- 表情按原稿语义安排，知识对象先让位，标题/结论/字幕保留，之后按分镜恢复或进入下一场。沿用固定seed的表情策略，素材不足说明原因，不照搬kb-049的6处。
- 代表样片覆盖角色和关键内容动作，再扩展全片。回读真实草稿与MP4中的素材、字幕、动作参数，并查看进入、操作中、停稳、退出/衔接画面；单纯关键帧计数不证明效果正确。
- 结构检查、逐帧/多阶段画面检查、完整连续审看、配音审听、剪映UI打开与播放分别记状态。播放到片尾、联系表或磁盘登记均不能单独证明全片连续审看通过。未做的检查不填true，保持待审核；不为过门禁伪造证明。

冻结此规则不自动修改旧项目、不重新出图、配音或渲染，也不自动回写飞书或发布。
